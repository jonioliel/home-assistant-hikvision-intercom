# Video media — rc.37 source-confirmed behavior and Arx guidance

## WisKey MSE and RTC bridges

`GET /api/hikvision_intercom/mse/{station_id}` and `/rtc/{station_id}` upgrade to WebSocket under HA authentication. Both require the authenticated HA user to have the station in scope and `overview:view` or `stations:view`. Unknown/unloaded/non-streaming stations return 404; denied returns 403; each bridge permits 12 active sockets and returns 429 above its own limit; a mismatched global transport/mode returns 409. The limit is per WisKey HA view instance, not per operator, and does not apply to Arx's separate go2rtc relay. HA or browser network proximity is no authorization shortcut.

MSE mode requires `transport="webrtc"`, `webrtc_mode="mse"`. Within 10 seconds of upgrade the client sends exactly `{"codecs":[...strings]}` from the allowlist (`avc1.640029`, `avc1.64002A`, `avc1.640033`, `hvc1.1.6.L153.B0`, `mp4a.40.2`, `mp4a.40.5`, `flac`, `opus`). WisKey forwards to go2rtc; it sends `{"type":"mse","value":"video/mp4; codecs=..."}` followed by binary fMP4 segments, or `{"type":"error","code":"..."}` then closes. MSE initial upstream connection is bounded to 10 seconds, per-forward receive to 12 seconds, downstream send to 3 seconds, frame size to 4 MiB. Client commands after greeting are invalid. Local bridge errors include `mse_protocol_error`, `mse_codec_unavailable`, `mse_connection_lost`, `mse_session_changed`.

RTC mode requires `transport="webrtc"`, `webrtc_mode="rtc"`. Within 10 seconds the client sends exactly `{"offer":"<SDP>"}`, at most 262144 characters, beginning `v=0`, with audio/video sections marked `a=recvonly` and no `sendrecv`/`sendonly`. WisKey sends `{"type":"answer","answer":"<SDP>"}`, then zero or more `{"type":"candidate","candidate":{"candidate":"...","sdpMid":"0"}}`. The browser sends candidate messages as `{"candidate":"candidate:..."}` and can send `{"type":"ping"}` to receive pong. The first answer has a 15-second upstream timeout; browser messages have a 35-second timeout, up to 100 candidate messages, each at most 4096 characters. Local errors include `rtc_protocol_error`, `rtc_signaling_failed`, `rtc_connection_lost`, `rtc_session_changed`.

Both views recheck station/view grant, runtime identity and media setting revision every 0.5 seconds, then close when invalid. They forward only allowlisted local error codes, not go2rtc text that might contain credentials. Source URLs remain on the HA side. Browser HA sign-path behavior belongs to HA authentication and frontend APIs; this package does **not** promise a particular refresh-token binding or signed-path TTL because WisKey code does not define it.

## Camera entity and Arx's own relay

`IntercomCamera.stream_source()` is implemented as `runtime.client.settings.rtsp_source()` only when `runtime.profile.stream` is true. Today `rtsp_source()` returns credential-bearing RTSP channel `/Streaming/Channels/101`. This is an HA camera method, **not** a frozen external WisKey contract. Channel 102 is not exposed here. Password/host changes flow through the station runtime/settings after reload; no immediate-rotation guarantee is published. `async_camera_image()` uses the station snapshot route when supported; its client caches a successful snapshot for 2 seconds and serializes fetches with a lock. This is not a promise of safe polling frequency across viewers or stations.

We have no verified per-model concurrent RTSP session matrix. Do not assert 10, 12 or any fixed Hikvision upstream capacity without an on-site test. Arx can use its own go2rtc for the native wall, but it must keep credential-bearing source retrieval on the backend, opt in per camera, intersect Arx RBAC with live WisKey station/view scope, lease and stop viewers on revocation, and measure upstream session count. Using the same go2rtc instance as WisKey is possible through `media/settings_update.go2rtc_url` if the configured provider is reachable and valid, but WisKey currently passes source URLs dynamically and does **not** guarantee stream deduplication with Arx's named streams. Test before promising one upstream pull. The WisKey MSE/RTC 12-socket cap does not constrain streams that never touch those bridges.

For Arx-native video the supported first prototype is an authorized HA camera/stream path or a narrowly specified backend-only media adapter. A new backend-only `stream_source` contract and channel-102 option would be additive future work requiring capability detection and tests. They are not part of rc.37.
