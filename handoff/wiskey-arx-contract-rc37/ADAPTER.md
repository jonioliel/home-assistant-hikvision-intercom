# Code handoff for Arx — read-only integration slice

`examples/arx-readonly-client.mjs` is a small, framework-neutral client that Claude can import into Arx's existing bridge/frontend. It accepts an injected transport implementing `call(type,payload)` and `subscribe(type,onEvent)`. The transport must already represent the real HA operator; this sample **does not solve identity delegation**, authenticate to HA, expose a generic WS proxy, carry credentials or send any mutation. It obtains `authorization/session`, `overview/summary` and `subscribe`, checks advertised API compatibility and handles `refresh`, `access_revoked` and `screen_locked`. Unit tests use fake transport and are included.

Arx should wrap its existing bridge with this narrow interface. Implement a typed Arx server endpoint for each projection; never accept a browser-provided arbitrary WisKey `type`. For service-token discovery, restrict output to non-personal health data and do not grant station viewers based solely on a privileged service account. Once a per-user transport is proven, the same read-only client can run with that user's identity. Reconnect must construct a new client and repeat session/overview/subscribe; `close()` must release the subscription.

We are **not** shipping a reusable `@wiskey/components` bundle in rc.37. Current `panel.js` is a Home Assistant custom panel expecting `hass`, global route and media helpers. Packaging its seven components would require a versioned host adapter, navigation events, style-token contract, lifecycle tests and a media provider interface. The frontend source is supplied as implementation reference, but importing arbitrary classes without their host assumptions is unsupported. Under Arx's current Ingress UI there is no `hass`, `auth/sign_path` or generic camera stream support; overview cards, person detail, events and station cards are the first plausible extraction candidates, while live camera, call/audio controls and capture need additional transport hooks. No ETA is committed.

For native styling, prefer Arx's own design tokens and the WisKey source as a visual reference. No WisKey CSS custom-property list is presently a stable public override contract. Current components may call global navigation or rely on HA Lit internals; a future package would need an additive `wiskey-navigate` event, explicit `language`/`dir`, lifecycle teardown and `mediaProvider` with authorization. These event names are proposals, not rc.37 APIs.
