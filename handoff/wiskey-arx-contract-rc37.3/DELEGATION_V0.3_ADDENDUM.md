# Delegation v0.3 addendum — design only · 2026-10-01

Extends v0.2; changes are explicit below. Not implemented and not a callable/public protocol. v0.2 provisional command/envelope/error names remain provisional.

2. First proof-flow acceptance target: HA local homeassistant provider and configured TOTP. Do not downgrade or bypass MFA. Generic providers are outside initial promised scope. Current source selects local credentials and transports login flow forms, but delegated proof/TOTP live acceptance is NOT_RUN. Require a fresh same-user proof bound to the delegated session; reject replay/expiry/revocation. Current source's successful local reauth unlocks and elevates together; separating proof purposes in the new transport is a new design obligation, not a claim about rc.37 behavior. Review preservation of equivalent policy before activation.
3. Proposed D-007 heartbeat every20s; timeout at60s from last authenticated server receipt using monotonic time. Bridge may heartbeat only while the bound Arx login is valid. Do not treat untrusted caller timestamps as renewal. Detect expired timeout on API entry as well as scheduled cleanup. A late heartbeat cannot reopen a closed session. Known disconnect/logout/disable/revoke closes without waiting. Heartbeat never resets PanelSecurity idle/elevation. Lifecycle timeout does not guarantee universal HA logout detection.
4. Session cannot outlive Arx login; no resurrection after restart. Absolute lifetime and renewal rules remain unresolved; remote Arx's reported30min access-token storage is not automatically the delegation TTL or login lifetime. Reissue capability/session only under approved lifecycle and fresh policy.
5. Initial WisKey private challenge lifetime120s remains a proposal from v0.2. Existing local flow/elevation300s is separate. Their interaction requires tests; no runtime setting is changed here.
6. B0 removes background last_access entirely, including stale cache snapshots and outputs following reconnect. Arx current memory cache/UI disclosure remains until code change. WisKey's proposed minimal projection is an additive separate output, not a silent change to overview. See BACKGROUND_PROJECTION_DRAFT.md.
