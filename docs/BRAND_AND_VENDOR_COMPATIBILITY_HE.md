# מיתוג smplwise access control ותאימות התקנות קיימות

השם הגלוי של האינטגרציה ב־Home Assistant וב־HACS הוא **smplwise access control**. WisKey נשאר כינוי הממשק הקיים. העץ המקומי מכין domain חדש: `smplwise_access_control`; הוא עדיין לא הופץ למערכת החיה. תמיכה ביצרנים אחרים, לרבות Akuvox, תחייב מתאם פרוטוקול ואימות נפרדים.

## מזהים ומעבר

- `hikvision_intercom` הוא המזהה של הגרסאות המותקנות. הוא קשור לרשומות תחנות, ישויות, שירותים וקובצי נתונים פרטיים. לא ניתן לשנות אותו רק על ידי שינוי שם ה־manifest או התיקייה.
- קוד גרסת המעבר משנה את שם התיקייה, ה־domain, פקודות WebSocket, שירותי HA, מסלולי API ופאנל ל־`smplwise_access_control` / `smplwise-access-control`.
- כלי מעבר במצב בדיקה יבשה ובמצב כתיבה עם גיבוי מכין העברת config entries, רישומי ישויות, מזהי מכשירים וקובצי `.storage`. ראו [מסלול מעבר מלא](DOMAIN_RENAME_MIGRATION_HE.md). יש להריץ אותו רק אחרי בדיקה על עותק וכאשר HA כבוי.
- כתובות מאגר GitHub וקישורי Releases נשארים בשמם הקיים עד בדיקת התקנת HACS ושינוי המאגר; אין להציג קישור עתידי שאינו קיים.
- שמות Hikvision נשארים רק במחלקות הפרוטוקול ובתיאור תחנות שתואמות ל־ISAPI.

## הכנה ליצרנים נוספים

כשנוסיף Akuvox או יצרן אחר, ליבת הניהול תמשיך להגדיר משתמשים, הרשאות, אירועים והרשאות מפעילים. כל מחבר יצרן יספק יכולות מזוהות, מיפוי דלתות, קריאה/כתיבה בטוחה, מצב סנכרון ותיעוד היכולות שאינן נתמכות. אין להציג למשתמש פעולת ISAPI כפעולה כללית לכל יצרן לפני שיש לה מקבילה מאומתת במחבר החדש. הרחבת מחברים צריכה להיבדק גם בשמירת נתוני האינטגרציה הקיימת ולא לכלול שינוי domain אוטומטי.

לקראת מחבר נוסף יש להפריד בין ליבת מדיניות הגישה לבין מתאם התחנה: זיהוי יצרן ודגם בזמן ההוספה; חוזה יכולות מפורש עבור ממסרים, משתמשים, PIN, כרטיסים, אירועים, וידאו, שמע ולוחות זמנים; פעולות קריאה וכתיבה עם אימות תוצאה; ומיפוי שגיאות אחיד לליבה. יש לבדוק תחנה קיימת של Hikvision לצד תחנה של היצרן החדש באותה התקנה, כולל סנכרון חלקי, ניתוק והתאוששות, בלי לשנות את מזהי התחנות הישנות.


## בדיקת קבלה למעבר

1. כל התחנות והישויות נטענות עם אותם מזהי רשומה וישות, ללא כפילויות.
2. משתמשים, כרטיסים, PIN, קבוצות, הרשאות, אירועים, תזמונים ותבניות נשמרים.
3. השירותים, הפאנל ופקודות ה־WebSocket בשם החדש פועלים, וצרכנים חיצוניים מקבלים מפת שינוי.
4. התקנת HACS ועדכון גרסה נוספת נבדקים, כמו גם שחזור מגיבוי למהדורה הישנה.
