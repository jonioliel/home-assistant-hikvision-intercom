# מעבר מ־`hikvision_intercom` ל־`smplwise_access_control`

## החלטה

`smplwise_access_control` יהיה מזהה האינטגרציה החדש, התיקייה תחת `custom_components`, קידומת השירותים ופקודות WebSocket, ונתיב הפאנל. `Hikvision` יישאר רק בשם מתאם היצרן ובמונחי ISAPI שבהם הוא מדויק. השם הגלוי של המוצר הוא **smplwise access control**.

זהו מעבר אינטגרציה, לא שינוי טקסט. Home Assistant מזהה config entries וישויות באמצעות ה־domain; שינוי manifest ותיקייה בלבד משאיר את ההתקנה הקיימת ללא תחנות פעילות. אסור להפיץ את השינוי כך.

## מה חייב לעבור יחד

| שכבה | מזהה קיים | טיפול נדרש |
| --- | --- | --- |
| HA config entries | `domain: hikvision_intercom` | להעביר את כל רשומות התחנות תוך שמירת `entry_id`, נתוני התחברות, אפשרויות, מיפוי ממסרים ו־`unique_id` |
| רישום ישויות | `platform: hikvision_intercom` | להעביר את הבעלות ל־domain החדש תוך שמירת `entity_id`, שם, אזור והעדפות |
| רישום מכשירים | קישורים ל־`entry_id` | לוודא שהקישורים נשארים תקפים ושאין מכשירים כפולים |
| `.storage` | `hikvision_intercom.*` | לשכפל למפתח החדש, לתקף מעטפות ותוכן, ולשמור את המקור לשחזור |
| ממשק ו־API | פאנל, static, `/api/`, WebSocket, שירותים | להעביר את המסלולים והצרכנים יחד; לספק הודעת מעבר למי שמשתמש בכתובות או פעולות ישנות |
| HACS | תיקיית אינטגרציה אחת במאגר | לבדוק התקנה ועדכון של התיקייה החדשה; לא לארוז שתי אינטגרציות באותו מאגר HACS |
| אוטומציות חיצוניות | קריאות לשירותי `hikvision_intercom.*` | לאתר ולהעביר במפורש; לא להניח שקבצי YAML או מערכת VMS יתעדכנו לבד |

## בדיקה מקדימה של כלי המעבר

הכלי המקומי `tools/migrate_domain_offline.py` קורא תיקיית קונפיגורציה של Home Assistant ואינו משנה אותה ללא `--apply`. הפלט מכיל מונים בלבד. תחילה הרץ על **עותק** של תיקיית הקונפיגורציה:

```powershell
python tools/migrate_domain_offline.py C:\path\to\ha-config-copy
```

רק אחרי בדיקה על עותק מלא, כש־HA כבוי וגיבוי מלא זמין, ניתן להפעיל עם `--apply --ha-stopped`. הכלי יוצר ZIP עם קבצי הליבה המקוריים לפני כתיבה, משאיר את קובצי ה־`.storage` הישנים, ונכשל אם מוצא כבר נתוני domain חדש או קובץ פגום. ה־ZIP מכיל פרטי גישה רגישים ויש לשמור אותו במקום פרטי.

```powershell
python tools/migrate_domain_offline.py C:\path\to\ha-config-copy --apply --ha-stopped
```

**בדיקת הפלט הסטטי אינה מוכיחה שהתחנות פועלות.** לפני התקנה חיה צריך להריץ Home Assistant על עותק, לאמת קליטת הרשאות, אירועים ומכשירים, ולבדוק את HACS. קוד שירות או WebSocket ישן באוטומציות או ב־VMS חיצוני אינו עובר באופן אוטומטי.

## סדר ביצוע בטוח

1. לבנות מהדורת מעבר מקומית עם ה־domain החדש ולשמור את המהדורה הנוכחית כהפצה שניתן לחזור אליה.
2. ליצור כלי **בדיקה יבשה** עבור גיבוי HA: הוא סופר רשומות תחנות, ישויות, קובצי נתונים ומפנה להתנגשויות, בלי להציג סיסמאות, PIN או מספרי כרטיס.
3. ליצור כלי מעבר חד־פעמי לעבודה רק כאשר HA כבוי. הכלי יוצר גיבוי קודם לכתיבה, מאמת מראש את כל קובצי ה־JSON, מכין את כל השינויים, כותב באופן אטומי ובודק את התוצאה. במקרה שגיאה הוא עוצר ומשחזר; קובצי המקור נשמרים.
4. על עותק מלא של תיקיית HA, להתקין את תיקיית `custom_components/smplwise_access_control`, להסיר מן העותק את `custom_components/hikvision_intercom` רק אחרי הגיבוי, להריץ את הכלי ולבדוק טעינת כל התחנות, משתמשים, הרשאות, קבוצות, אירועים, תוכניות דלת, הגדרות, תמונות ותבניות. לבדוק שלא נוצרו ישויות או מכשירים כפולים, ושהרשאות דלת אינן משתנות.
5. לבדוק התקנה ועדכון של HACS, בניית ממשק, בדיקות Python ו־HA, חזרה לגרסה הישנה מגיבוי, וצרכני API חיצוניים.
6. רק לאחר מעבר מלא על עותק: לתאם חלון מעבר בהתקנה החיה, ליצור גיבוי HA מלא, לעצור HA, להחליף את תיקיית הקוד הישנה בחדשה, לבצע את מעבר הנתונים, להפעיל HA ולבדוק תחנה אחת ואז את הצי כולו. לשחזור יש להחזיר גם את קוד ה־domain הישן וגם את קובצי הנתונים מגיבוי.

## תנאי קבלה

- מספר התחנות, המשתמשים, הכרטיסים, ההרשאות, האירועים ולוחות הזמנים לפני ואחרי זהה; אין מחיקה שקטה או שכפול.
- לכל ישות קיימת נשמר `entity_id` וקישור למכשיר, או מוצג במפורש מיפוי שינוי לפני החלתו.
- תקלת תחנה אחת אינה עוצרת את המערכת או סנכרון תחנות אחרות.
- אוטומציות המשתמשות בשם השירות הישן מזוהות לפני המעבר ולא נשארות שבורות ללא הודעה.
- HACS מציע את העדכון הבא תחת האינטגרציה החדשה, ואפשר לשחזר את הגרסה הישנה מגיבוי.

ה־domain החדש הוכן בעץ המקור המקומי, וכלי הבדיקה והמעבר נמצא ב־`tools/migrate_domain_offline.py`. עד שכל התנאים האלה נבדקים על עותק של HA, אין לפרסם את המהדורה או להריץ שינוי על HA החי.
