# החלפת תחנה והוצאה משימוש — rc.22

## המסלול שנוסף

בכלי ניהול ← ניהול צי ודוחות ← השפעת החלפה והוצאה משימוש:
בחר מקור וחלופה ריקה, או מקור ללא חלופה להוצאה משימוש.
סקור את ההשפעה והכן תוכנית שמורה. קרא את התוכנית השמורה עצמה לפני אישור.
ההכנה קוראת את זהות התחנות ואת המלאי; היא אינה משנה הרשאות בציוד.

החלת תוכנית משנה בכתיבה אטומית אחת את קבוצות ההרשאה, החריגים האישיים,
בחירות המנעולים ואנשים מושפעים. הרשאה שניתנה מקבוצה נשארת ירושה מקבוצה;
חסימה אישית נשארת חסימה. מזהי העובדים, הכרטיסים וה־PIN נשארים אותם מזהים.
השם ופרטי התחנה — אזור, אחראי, תגיות, ספי התראה וחלון תחזוקה — מועתקים בשלב נפרד מתועד.
ניתן להמשיך שלב זה לאחר כשל שמירה, בלי להעביר שוב הרשאות.

לאחר ההחלה מנגנון הסנכרון הקיים מבצע את הכתיבות והביטולים מול התחנות,
עם יומן בעלות וקריאה חוזרת. התוכנית ממתינה לאימות; חיבור המקור נשאר קיים.
יומני ביטול ו־PIN/כרטיס שנמצאים בניקוי אינם נמחקים כדי לקצר את ההמתנה.
אי אפשר להחזיר למקור הרשאות מרכזיות או לפתוח בו תוכנית פתיחה חדשה.

לחץ ״אמת סנכרון וניקוי״. האימות קורא מלאי טרי משתי התחנות,
בודק שאין חשבונות/כרטיסים או ביטולים ממתינים במקור,
ומשווה את התוצאה בחלופה ליומן הבעלות, לרוויזיות ולשדות הגישה בפועל.
נוכחות מספר עובד בלבד אינה מספיקה. גם שינוי אדם אחרי ההחלה נבדק מול
המצב העדכני; הוא אינו גורם להרצה נוספת של העברת ההרשאות.

רק לאחר האימות מוצעת הסרת חיבור המקור. ההסרה דורשת אישור ידני נוסף
וקריאה חוזרת נוספת. כוונת ההסרה נשמרת לפני הסרת החיבור, כדי שניתן יהיה
להמשיך לאחר נתק או אתחול. אין כאן איפוס מפעל או מחיקת קודים ציבוריים.

## אישור ומגבלות

- פעולות אלה זמינות רק למנהלים פעילים. אם אישור כפול פעיל בעת ההכנה
  או הביצוע, מנהל אחר צריך לאשר את אותה תוכנית. האישור אינו מתחיל ביצוע.
  הפעלת המדיניות אחרי העברה מאפשרת לאסוף אישור נפרד לפני הסרת החיבור.
  חשבון יוזם/מאשר שבוטלה פעילותו אינו מתקבל כאישור תקף.
- זהות שני רכיבים חייבת להיות שונה. מיפויי מנעולים דורשים אישור פיזי
  באשף התחנה, וצריכים לכלול את כל המנעולים שבהרשאות המועברות.
- חלופה שכבר משויכת לקבוצה, לאדם, ליומן בעלות או לביטולים אינה נדרסת.
  חשבונות לא מוכרים במקור או חשבונות/כרטיסים בחלופה חוסמים הכנה.
- לוחות משתמש שנפרסו מקומית ותוכניות פתיחת דלת מחייבים טיפול נפרד.
  המסלול חוסם אותם; הוא אינו מעתיק לוח מקומי בלי פריסה וקריאה חוזרת.
  גם תוכנית פתיחה מושהית נחשבת תוכנית קיימת עד למחיקתה במסלול הרגיל.
- תוכנית שלא הוחלה תקפה ל־24 שעות ומחייבת נתונים תואמים לפני הביצוע.
  תוכנית שהוחלה נשמרת עד השלמת הניקוי; אין פקיעת זמן שמוחקת ביטול ממתין.
- ביטול/היפוך של העברה שכבר הוחלה, העברת בעלות על תוכנית ליוזם חדש
  או החלפת מאשר שבוטל, אינם ניתנים במסירה זו. אין לבצע עקיפה באמצעות
  מחיקת יומנים. אלה מסלולי המשך נפרדים, אם נדרשים תפעולית.
- הסרה דרך המסלול מאמתת הרשאות מנוהלות. הסרה ידנית של חיבור מחוץ למסלול
  אינה מקבלת מכך הוכחת ניקוי של הציוד.

## אחסון ותאימות

סכמת מאגר הגישה עולה ל־14. ההגירה מוסיפה יומן תחנות לסכמות הנתמכות
ושומרת אנשים, קבוצות, בעלות וביטולים. חזרה לקוד ישן דורשת גם גיבוי נתונים
תואם; אין להפעיל קורא סכימה ישן על המאגר החדש.
ה־domain נשאר `hikvision_intercom`; כל העיצובים וחוזה VMS v1 נשמרים.

## API עבור VMS

יכולת גילוי: `station_lifecycle_transactions`, לצד
`station_lifecycle_review` הקיימת. כל הפקודות הן WebSocket תחת
`hikvision_intercom/platform/`, עם אימות מנהל בצד השרת:

| פקודה | שדות נדרשים מעבר ל־id/type |
| --- | --- |
| lifecycle_prepare | source_id, target_id; מחרוזת ריקה ללא חלופה |
| lifecycle_jobs | ללא שדות נוספים |
| lifecycle_plan | job_id, fingerprint |
| lifecycle_decide | job_id, fingerprint, approve, confirmed |
| lifecycle_apply | job_id, fingerprint, confirmed |
| lifecycle_verify | job_id, fingerprint, confirmed |
| lifecycle_remove | job_id, fingerprint, confirmed |

`api_contract: 1` נשאר אופציונלי ותואם לחוזה הקיים.
הכנה מחזירה job ו־impact; קריאת תוכנית מחזירה גם metadata ומיפויים מאומתים.
רשימת התוכניות מסוננת מסודות ומזהים פרטיים של מפעילים.
`own_request` ו־`require_approval` מאפשרים התאמת פקדים.
מצבים: prepared, applied, verified, removing, removed, rejected.
אין להסיק ניקוי מ־applied או מסגירת חיבור. תוצאת האימות כוללת
`managed_access_cleanup_verified`, `source_removal_ready` ו־pending_cleanup.
`factory_reset_performed` הוא false.
תשובה שאבדה: קרא lifecycle_jobs לפני ניסיון חוזר; apply אינו מעביר שוב
תוכנית שכבר הוחלה ו־remove אינו מסיר שוב תוכנית שהושלמה.
סכמות השדות המלאות מופקות מתוך רישום הפקודות במסמך
[קטלוג הפקודות](integrations/WISKEY_VMS_PANEL_COMMANDS.json).

## בדיקות ומצב התוכנית

בדיקות התוכנה משתמשות במוקים ובשתי תחנות סימולטור, כולל תשובה שאבדה,
כשל שמירה, חסימה מקבוצה, חריגים אישיים, מחיקה ואימות תוכן מלא.
אין להציג זאת כהסמכת חומרה. לא נעשתה כתיבה לצי החי בלילה.
זו מסירת ביצוע של חבילות 7–8 במסלול המבוקר המתואר; המשכי מחזור חיים
המפורטים במגבלות וחבילות 9–11 נשארים פתוחים.
